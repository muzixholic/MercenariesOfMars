# 기체·파일럿·유닛 편성

성장 프리셋·능력치 범위·적군 자동 레벨은 [최신 성장 설정 안내](파일럿성장프리셋안내.md)를 참고한다.

## 데이터 구성

전투 유닛은 **기체 + 파일럿 + 진영**의 편성으로 구성한다. 기존 `CharacterDefinition` 에셋은 편성 연결 역할을 맡으므로 씬과 맵의 기존 유닛 참조를 유지한다. 같은 파일럿을 다른 기체로 바꾸거나 같은 기체 정의를 여러 편성에서 사용할 수 있다. 각 전투 유닛의 현재 HP·EN·행동 상태는 별개다.

| 데이터 | 편집 항목 |
|---|---|
| 기체 | 이름, 맵 아이콘, HP, EN, 장갑치, 조준치, 운동성, 이동 가능 지형(지상·공중·우주 복수 선택), 이동력, 가격, 장비 리스트(기존 스킬 에셋을 무장으로 사용), 설명 |
| 파일럿 | 이름, 레벨, 누적 경험치, 공격력, 방어력, 명중력, 회피력, 포트레이트 리스트, 설명 |
| 유닛 편성 | 편성 이름, 기체, 파일럿, 기본 진영 |

파일럿 레벨은 1~99, 공격·방어·명중·회피는 1~999다. 가격은 0~9,999,000 정수이며 화폐 단위와 수리·구매·매각·격추 보상 비율은 정하지 않았다.

## 기체 기본 능력치 범위와 개조

| 기본 능력치 | 입력 범위 | 개조 대상 |
|---|---|---|
| HP | 1,000~9,999,000 | HP 개조 |
| EN | 10~990 | EN 개조 |
| 장갑치·조준치·운동성 | 각각 10~9,990 | 각각 별도 개조 |
| 이동력 | 1~99 | 해당 없음 |
| 가격 | 0~9,999,000 | 해당 없음 |
| 허용중량 | 0~990 | 해당 없음 |

**화성의 용병단 → 기체 에디터**에서 기본값과 HP·EN·장갑치·조준치·운동성·무장의 6개 개조 단계를 설정한다. 단계는 각각 0 이상이며 캠페인의 최대 개조 단계까지만 실제 전투에 적용한다. 기본 상한은 10이다. `적용값 = 기본값 × (100 + 개조 단계 × 5) ÷ 100`으로 계산한다. 복리 대신 기본값의 5%씩 더하고, 소수점 이하는 버린다. 기본값 상한은 개조 적용값의 상한이 아니다. 예를 들어 HP 9,999,000의 10단계 적용값은 14,998,500이다. 입력 범위를 벗어난 기존 기체 값은 편집·검증 시 범위 안으로 제한하고 전투에서도 범위를 적용하며, 기존 파일의 일괄 저장이나 수치 비례 변환은 하지 않는다. 기체가 없는 이전 캐릭터 데이터에는 이 범위를 적용하지 않는다.

무장 개조는 기체에 저장한다. 기본 공격력 1,000인 동일 무장을 0단계 기체 A에 장착하면 1,000, 5단계 기체 B에 옮겨 장착하면 1,250이다. 무장 에셋의 공격력은 바뀌지 않는다. 기체 에디터 장비 목록에는 기본 공격력과 개조 공격력을 함께 표시한다. 전투 시작 시 적용값을 복사하므로 전투 도중 원본·개조 단계를 변경해도 진행 중인 전투는 유지하고 다음 전투에 반영한다. 공격·반격·무장 선택·피해 예측은 같은 적용 공격력을 사용한다.

같은 기체 에셋을 여러 편성에서 공유하면 개조 단계도 공유한다. 개별 기체별로 다르게 설정하려면 별도 기체 에셋을 사용한다. 이동력·가격·허용중량·무장 EN 소모·잔탄·무게에는 개조 보정을 적용하지 않는다. 장갑치·조준치·운동성은 개조 적용값을 표시하지만, 아래의 기존 전투 계산 규칙을 유지한다.

### 개조 비용

무장은 **목표 단계 × 5,000**, HP·EN·장갑치·조준치·운동성은 각각 **목표 단계 × 3,000**이다. 각 항목은 자신의 현재 단계로 비용을 계산한다. 10단계 초과 해금 후에도 같은 규칙을 유지한다.

| 개조 구간 | 무장 | 나머지 각 항목 |
|---|---:|---:|
| 0→1 | 5,000 | 3,000 |
| 1→2 | 10,000 | 6,000 |
| 4→5 | 25,000 | 15,000 |
| 9→10 | 50,000 | 30,000 |
| 0→10 합계 | 275,000 | 165,000 |

기체 에디터의 **다음 1단계 개조 비용**에서 항목별 견적을 확인한다. 에디터에서 직접 단계를 변경하는 작업은 데이터 작성이므로 자금을 차감하지 않는다. 인터미션 개조 화면에서 구매를 확인하면 자금을 차감한다. 자세한 설정은 [인터미션 안내](인터미션안내.md)를 참고한다. 공통 계산 함수는 `MechUpgradeCost.NextStage(항목, 현재단계)`와 `MechUpgradeCost.Total(항목, 현재단계, 목표단계)`이며, 금액은 64비트 정수로 계산한다. 여러 단계는 각 단계 비용의 합계를 사용하며 표현 불가능한 합계는 오류로 처리한다.

비용 규칙 변경 파일은 `Runtime/MechUpgradeCost.cs`, `Runtime/MechDefinition.cs`, `Editor/MechPilotEditors.cs`, `Tests/Editor/MechUpgradeCostTests.cs`와 이 문서다. 추가 Inspector 연결이나 씬·프리팹 변경은 필요 없다.

추가 Inspector 연결은 필요 없다. 기체 에셋을 열어 기본값과 개조 단계를 설정하고 저장하면 된다. 이번 변경은 `Runtime/MechDefinition.cs`, `Runtime/CharacterDefinition.cs`, `Runtime/SkillDefinition.cs`, `Runtime/BattleSession.cs`, `Runtime/BattleController.CampaignUI.cs`, `Runtime/BattleController.Deployment.cs`, `Editor/MechPilotEditors.cs`에 반영했다. 검증은 `Tests/Editor/MechUpgradeTests.cs`, `Tests/Editor/MechPilotTests.cs`, `Tests/PlayMode/MechPilotIntegrationTests.cs`, `Tests/PlayMode/WeaponSelectionViewTests.cs`에서 수행한다.

누적 경험치는 0 이상 정수로 파일럿 에디터에서 입력하며 전투 상세 능력 화면에도 표시한다. 경험치 획득·필요 경험치·경험치에 따른 자동 레벨업은 아직 없다. 파일럿 레벨과 적군 자동 레벨에 따른 성장 커브는 적용한다. 경험치만 바꾸면 레벨은 바뀌지 않는다. 추가 Inspector 연결은 필요 없다.

## 캠페인 진행에 따른 최대 개조 단계 해금

1. 캠페인 에셋을 선택하거나 캠페인 에디터의 설정에서 **시작 최대 개조 단계**를 지정한다. 기본값은 **10**이며 0 이상으로 설정한다.
2. 조립형 스크립트 에디터에서 명령을 **최대 개조 단계 증가**로 선택하고 **최대 개조 단계 증가량**에 1 이상의 정수를 입력한다. 예를 들어 증가량 5는 현재 상한을 10에서 15로 올린다. 이 명령은 인트로·맵 이벤트·아웃트로 모두에서 쓸 수 있다.
3. 아웃트로에 명령을 배치하면 클리어 후 인터미션에서 올라간 상한을 확인할 수 있고 다음 미션으로 이어진다. 상한 해금은 기체의 실제 개조 단계를 자동으로 올리거나 비용을 차감하지 않는다.

현재 값은 캠페인 진행 변수 `CampaignFlow.MaxUpgradeStage`에 저장하며 `BattleController.MaxUpgradeStage`에서도 읽을 수 있다. 원본 캠페인 에셋의 시작값과 기체 에셋의 개조 단계는 실행 중 해금으로 바꾸지 않는다. 최대 단계 증가량은 정수 최댓값에서 안전하게 제한한다. 인터미션 저장·불러오기로 현재 개조 상한을 보존한다.

스테이지 재시작은 해당 스테이지 진입 당시의 상한을 복원하고 인트로를 재생하므로 같은 이벤트가 누적되지 않는다. 다음 미션에 도달해 얻은 상한은 그 미션을 재시작해도 유지한다. 타이틀에서 새 캠페인을 시작하면 캠페인 파일의 시작값을 다시 사용한다.

기체 에디터는 10단계 초과도 입력할 수 있고 캠페인 상한 적용 전 미리보기를 표시한다. 전투 시작 시 6개 개조 단계 각각을 현재 캠페인 상한으로 제한해 수치를 복사한다. 예를 들어 기체의 무장 개조가 20이고 상한이 15면 기본 공격력 1,000은 1,750으로 적용된다. 이미 진행 중인 전투의 수치는 해금 이벤트로 소급 변경하지 않고 다음 전투부터 반영한다.

단독 맵 테스트는 상한 10을 사용한다. 캠페인이 없는 이벤트에서 이 명령을 실행하면 안내 오류로 중단한다. 스테이지 단독 테스트는 임시 캠페인 기본값 10으로 명령을 검증할 수 있으며, 다른 시작값을 검증하려면 실제 캠페인 에셋을 사용한다. 추가 씬·프리팹 연결은 필요 없다.

이번 연결 파일은 `Runtime/CampaignDefinition.cs`, `Runtime/CampaignFlow.cs`, `Runtime/EventSequence.cs`, `Runtime/EventRunner.cs`, `Runtime/MechDefinition.cs`, `Runtime/SkillDefinition.cs`, `Runtime/BattleSession.cs`, `Runtime/PilotProgressionSettings.cs`, `Runtime/BattleController.cs`, `Runtime/BattleController.CampaignUI.cs`, `Runtime/BattleController.Deployment.cs`, `Editor/EventCommandDrawer.cs`, `Editor/EventSequenceEditor.cs`, `Editor/MechPilotEditors.cs`다. 검증은 `Tests/Editor/MechUpgradeTests.cs`, `Tests/Editor/EventEditorTests.cs`, `Tests/PlayMode/CampaignFlowTests.cs`, `Tests/PlayMode/EventTests.cs`에서 수행한다.

## 현재 적용 범위

요청에 따라 **새 기체·파일럿 합산 계산식은 도입하지 않는다**.

- 전투의 최대 HP·EN·이동력·맵 아이콘·사용 무장 목록은 기체에서 읽는다.
- 레벨·공격력·방어력·명중력·회피력과 대사 포트레이트는 파일럿에서 읽는다.
- 기존 피해·명중 계산 구조를 유지한다. 파일럿 공격력+무장 공격력−파일럿 방어력에 기존 지형 보정·대응 규칙을 적용한다. 최종 명중 확률은 기존처럼 0~100%로 제한한다.
- **장갑치·조준치·운동성은 저장·표시만 하며 기존 전투 수치에 더하지 않는다.** 가격은 인터미션 기체 구매에 사용하며 수리·매각은 보류한다.
- **이동 가능 지형 유형도 저장·표시 단계**다. 지상·공중·우주를 기준으로 한 맵 통행 판정, 비행 고도, 바다 횡단, 구조물 비행 통과는 아직 추가하지 않는다. 현재의 맵 이동 불가·이동 비용·점유 규칙을 유지한다.
- 전투 시작 시 수치와 무장을 복사하므로 편집기에서 원본을 바꾸어도 진행 중인 전투 수치는 바뀌지 않는다. 다음 전투에 반영된다.

## 작성 순서

1. **화성의 용병단 → 기체 에디터**에서 기체를 만들고 기체 능력치·맵 아이콘·이동 가능 지형·가격을 설정한다.
2. 장비 리스트의 `+`로 무장 스킬을 지정한다. **화성의 용병단 → 무장 에디터**는 기존 스킬 에디터를 열며, 공격력·사거리·EN 소모·이동 후 사용 여부를 설정한다. 무장 스킬 에셋을 여러 기체가 공유할 수 있다.
3. **화성의 용병단 → 파일럿 에디터**에서 파일럿과 능력치·포트레이트를 만든다. 표정 ID가 유지되어 목록 순서·표정 이름을 바꾸어도 기존 대사의 선택은 유지된다.
4. **화성의 용병단 → 유닛 편성 에디터 → 새 유닛 편성 만들기**에서 먼저 기체·파일럿·진영을 선택한다. **기체 이름 (파일럿 이름)**으로 편성 이름과 기본 파일명을 제안하며, **편성 저장**에서 저장 위치를 정한다. 선택한 기체·파일럿을 공유하는 편성 하나만 생성한다. 기체·파일럿이 없으면 각 선택란의 **신규**로 따로 저장해 바로 선택하고, **편집**으로 전용 에디터를 연다. 접힌 능력치 영역을 펼쳐 직접 수정할 수도 있다. 두 에셋이 지정되고 검증 오류가 없어야 편성을 저장할 수 있다. 저장 버튼은 편성과 연결된 기체·파일럿 모두 저장한다.
5. 맵 에디터의 유닛 배치에서 편성 에셋을 지정한다. 기체 또는 파일럿만 지정된 불완전한 새 편성은 검증에서 안내한다.

기존 **캐릭터 능력치 에디터** 메뉴도 유닛 편성 에디터를 연다. Unity 에셋 만들기 메뉴에서도 기체·파일럿·유닛 편성을 만들 수 있다. 맵 아이콘·포트레이트 이미지는 Sprite로 임포트해 지정한다.

기존 편성 Inspector에서도 기체·파일럿을 선택하거나 신규 생성할 수 있다. 참조를 교체하면 편성 이름을 자동으로 맞추며, 이름을 직접 수정하거나 **기체·파일럿 이름으로 맞추기**로 다시 계산할 수 있다. 기존 에셋 파일명은 자동으로 변경하지 않는다. 편성 생성을 취소하면 편성 파일을 만들지 않지만, 신규 버튼으로 이미 저장한 기체·파일럿과 직접 편집한 능력치는 유지한다. 추가 씬·프리팹 및 Inspector 연결 설정은 필요 없다.

편성 생성 흐름의 변경 파일은 `Editor/UnitFormationCreation.cs`, `Editor/CharacterEditorWindow.cs`, `Editor/CharacterDefinitionEditor.cs`이며, `Tests/Editor/UnitFormationCreationTests.cs`에서 참조 공유·자동 이름·신규 생성·잘못된 경로·덮어쓰기 방지를 검증한다.

## 대사 화자

조립형 스크립트의 대사 명령에서 **화자 파일럿**을 선택하면 파일럿 이름을 자동 사용하며 해당 파일럿의 포트레이트를 선택한다. 기체나 전투 편성이 없는 NPC 파일럿도 대사에 쓸 수 있다. 비워 두면 기존처럼 화자 이름을 직접 입력한다.

기존 대사의 캐릭터 화자 참조는 호환 연결로 남겨 둔다. 그 캐릭터가 기체·파일럿으로 분리되면 연결된 파일럿 이름·포트레이트를 읽는다. 기존 표정 ID와 직접 입력 이름을 보존한다. 기존 연결을 해제하거나 화자 파일럿을 새로 지정할 수 있다.

## 기존 데이터 변환

저장된 캐릭터 에셋의 Inspector에서 **기존 데이터를 기체·파일럿으로 분리**를 실행할 수 있다.

- 캐릭터 에셋과 GUID를 유지하고, 같은 폴더 아래 `기체/`, `파일럿/`에 새 에셋을 만든다.
- HP·EN·아이콘·이동력·스킬 목록은 기체로, 레벨·공격·방어·명중·회피·포트레이트는 파일럿으로 복사한다.
- 기존 진영·편성 이름·스킬 참조·포트레이트 ID를 유지한다. 기존 방어 수치는 파일럿 방어력으로 옮긴다. 새로운 장갑·조준·운동성·가격은 0에서 시작해 별도로 입력한다.
- 한 번 변환한 에셋은 다시 실행해도 기체·파일럿을 중복 생성하거나 이미 연결한 데이터를 덮어쓰지 않는다.
- 변환 전 데이터 필드는 호환용으로 남긴다. 새 편성에서는 기체·파일럿 값을 우선 사용한다. 옛 캐릭터 데이터만 있는 경우 기존 전투와 대사를 계속 읽을 수 있다.

이번 작업에서는 프로젝트에 저장된 기존 캐릭터 에셋도 이 방식으로 변환한다. 기존 씬·프리팹은 수정하지 않으며 Inspector의 씬 연결을 다시 할 필요는 없다.
