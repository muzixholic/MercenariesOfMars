# 아군 출격 칸과 영입 명단

## 맵 작성

1. **화성의 용병단 → 맵 에디터**에서 맵을 연다.
2. **아군 출격 칸** 도구를 고른다. 왼쪽 **도구** 탭에서 출격 ID 접두어를 지정할 수 있다.
3. 좌클릭·드래그로 출격 칸을 추가한다. 파란색과 출격 ID로 표시된다. 우클릭으로 제거하며 기존 Undo를 지원한다.
4. **배치** 탭이나 맵 Inspector의 **아군 출격 칸** 목록에서 ID와 좌표를 직접 편집할 수도 있다.
5. 적군과 고정 출격할 아군은 기존 **유닛 배치** 도구를 사용한다.
6. 검증 후 저장한다. 이동 불가 지형, 구조물, 고정 유닛, 다른 출격 칸과의 겹침 및 중복 ID를 검증한다.

출격 칸이 있으면 고정 아군이 없는 맵도 유효하다. 적군은 기존처럼 한 명 이상 필요하다. 출격 칸은 구조물과 고정 유닛 배치에서도 보호된다.

## 캠페인 영입 명단

캠페인 에셋의 **초기 영입 아군（유닛 편성）** 목록에 영입 상태로 시작할 아군을 등록한다. 등록 대상은 파일럿 단독 에셋이 아닌 **유닛 편성(CharacterDefinition)**이다. 파일럿 에셋을 사용할 때는 유닛 편성 에디터에서 기체와 파일럿을 연결하고 진영을 아군으로 지정한 뒤 등록한다.

명단은 캠페인 시작 때 복사하며 다음 스테이지로 이월한다. 재시작은 스테이지 진입 당시 명단을 복원하므로 영입·이탈 이벤트가 중복 누적되지 않는다. 인터미션에도 영입 명단을 표시한다. 캠페인의 고정 아군도 영입 명단에 기체·파일럿이 있어야 한다. 타이틀에서 새 캠페인을 시작하면 초기 명단으로 돌아간다.

조립형 스크립트에서 **아군 영입** 또는 **아군 이탈**을 고르고 **대상 아군 편성**을 지정한다. 이미 영입됐거나 이미 이탈한 파일럿이면 반복 실행해도 오류 없이 현재 상태를 유지한다. C#에서는 `전투진행기.Campaign.RecruitAlly(아군편성)`과 `RemoveAlly(아군편성)`을 사용한다. 같은 기체·파일럿의 중복 영입은 거절한다. 이탈은 대상 파일럿의 현재 편성을 명단과 전장에서 즉시 제거한다. 전투 중 마지막 아군이 이탈하면 패배하며, 이미 승리한 아웃트로의 이탈은 승리를 유지한다. 영입 목록과 편성은 인터미션 저장·불러오기로 보존한다. [인터미션 안내](인터미션안내.md)를 참고한다.

## 단독 테스트

맵 에디터의 **아군 출격 칸 → 도구** 또는 **배치** 탭에서 **단독 테스트용 영입 아군**을 등록한다.

- 맵 테스트는 이 명단을 사용한다. 명단이 비었으면 기존 고정 아군을 직접 사용하는 호환 테스트를 진행한다.
- 스테이지 단독 테스트도 이 명단을 초기 상태로 사용한다. 명단이 비었으면 그 맵의 고정 아군을 임시 초기 영입 명단으로 사용한다.
- 실제 캠페인은 테스트 명단을 사용하지 않고 캠페인의 영입 명단만 사용한다.

테스트 명단이 비어 있어도 맵 자체는 저장할 수 있지만, 고정 아군이 없으면 배치를 확정할 수 없다. 화면에 명단 설정 안내와 테스트 종료 버튼을 제공한다.

## 플레이 중 배치

캠페인은 **출격 준비 스크립트 → 출격 배치 → 인트로 → 전투** 순서로 진행한다. 배치가 확정되기 전에는 인트로·턴 진행·적 행동을 시작하지 않는다. 단독 맵 테스트는 기존처럼 출격 배치 후 맵 시작 이벤트를 실행한다.

- 맵의 파란 출격 칸을 클릭하거나 오른쪽 화살표로 현재 출격 칸을 선택한다.
- **영입된 아군 목록**에서 배치할 유닛을 선택한다.
- **선택 칸 해제**로 선택 칸의 배치를 취소한다.
- **자동 배치**는 이미 선택한 배치를 유지하면서 빈 칸을 명단 순서대로 채운다.
- **배치 확정 · 작전 시작**으로 전투에 진입한다.
- 휠 확대·축소와 클릭 드래그 시점 이동을 사용할 수 있다.

모든 칸을 채울 필요는 없다. 고정 아군이 없으면 한 명 이상 선택해야 한다. 같은 유닛·파일럿은 두 번 출격할 수 없으며 고정 배치된 유닛·파일럿도 선택 출격에서 제외된다. 배치 중에는 타이틀 또는 단독 테스트 종료로 빠져나올 수 있다.

선택 결과는 실행 중에만 보관한다. 원본 에셋은 변경하지 않는다. 패배 후 다시 시작하면 스테이지 진입 당시 명단을 복원하고 출격 배치를 다시 선택한다. 같은 기체·파일럿은 중복 출격할 수 없다.

## 고정 아군과 강제 편성

고정 아군의 기체·파일럿 조합을 캠페인 영입 명단에서 찾는다. 같은 조합이 있으면 영입 편성을 사용한다. 서로 다른 편성에 기체와 파일럿이 있으면 **강제 편성 알림**을 먼저 표시한다. **확인 · 지정 편성 적용** 후 두 편성의 기체를 교환하며, 남은 파일럿도 나머지 기체에 배정해 보유 자원을 보존한다. 이 편성은 다음 미션의 영입 명단에도 유지한다. 원본 편성·기체·파일럿·맵 에셋은 변경하지 않는다.

기체 또는 파일럿 자체가 미보유이면 자동 영입하지 않고 필수 배치 오류로 안내한다. 선택 영입 아군은 배치 조건을 지정한다. 여러 필수 배치가 같은 기체·파일럿을 요구하는 충돌도 오류로 거절한다. 같은 기체 에셋은 캠페인 명단에서 한 대의 자원으로 취급하므로 별개의 기체가 필요하면 별도 기체 에셋을 사용한다.

## 배치별 조건

맵 에디터 **배치 → 유닛 배치 → 배치 항목**에서 **배치 조건 결합**과 **배치 조건** 목록을 지정한다.

- **플래그**: 지정한 플래그 값을 확인한다.
- **아군 영입 여부**: 대상 편성의 파일럿 영입 여부를 확인한다. 기체 교환 후에도 같은 파일럿이면 영입 상태다.
- **기체 보유 여부**: 지정한 기체가 명단에 있는지 확인한다.
- **파일럿 영입 여부**: 지정한 파일럿이 명단에 있는지 확인한다.

기대값을 끄면 미영입·미보유·거짓 조건으로 반전한다. 목록이 비면 항상 배치하며 AND는 모두 만족, OR는 하나 이상 만족하면 배치한다. 예를 들어 `아군 영입 여부 = 참`과 `플래그 증원 허가 = 참`을 AND로 지정하면 두 조건을 만족하는 미션에서만 추가 아군이 출격한다. 적 배치에도 같은 조건을 사용할 수 있다.

조건은 출격 준비 스크립트 실행 후 명단·플래그로 한 번 평가한다. 불충족한 고정 아군은 자원을 예약하지 않는다. 같은 스테이지의 배치에 영향을 줄 영입·플래그는 출격 준비 스크립트에 지정한다. 출격 확정 후 실행되는 인트로·전투 중 영입은 **다음 출격부터** 배치할 수 있다. 전투 도중 조건 변경으로 자동 증원을 생성하지 않는다. 다음 미션의 조건부 배치는 이전 아웃트로에서 영입·플래그를 설정할 수도 있다. 조건부 배치도 서로 다른 ID·좌표를 사용해야 한다.

## 이번 스테이지 출격 선택 제한

1. 조립형 스크립트에 **이번 스테이지 출격 선택 제한** 명령을 추가한다.
2. **대상 아군 편성**을 지정하고 **출격 선택 제한**을 켠다. 끄면 같은 스테이지에서 다시 선택할 수 있다.
3. 스테이지 에디터 또는 스테이지 Inspector의 **출격 준비 스크립트（배치 선택 전에 실행）**에 해당 스크립트를 연결한다.

제한은 파일럿 기준이며 강제 편성으로 기체를 바꿔도 유지한다. 영입 명단에서 삭제하지 않고 해당 스테이지의 수동 선택·자동 배치만 막는다. 목록에는 회색 버튼과 제한 이유를 표시한다. 이미 선택 배치한 아군에게 제한을 걸면 그 선택은 해제한다. 고정·강제 출격은 유지하고 중복 선택을 막는다. 현재 전장의 유닛을 제거하는 명령은 아니며, 영구 이탈과 전장 제거가 필요하면 기존 **아군 이탈**을 사용한다.

다음 스테이지에 들어가거나 타이틀로 돌아가면 제한은 자동 해제한다. 재시작은 제한을 초기화하고 출격 준비 스크립트를 다시 실행하므로 동일한 배치 조건을 재현한다. 일반 플래그처럼 다음 미션으로 이월하지 않는다. C#에서는 `Campaign.SetDeploymentBlocked(아군편성, true/false)`와 `Campaign.IsDeploymentBlocked(아군편성)`을 사용할 수 있다.

출격 준비는 전투를 만들기 전에 즉시 실행한다. 영입·이탈·선택 제한·일반 플래그·개조 해금·플래그 분기·이벤트 종료를 지원한다. 대사·시간 대기·체력 변경·이동·공격·턴 종료는 지원하지 않으며 인트로에서 사용한다. 순환 분기는 실행 한도로 중단한다. 준비 스크립트는 고정 배치만 있는 스테이지에서도 실행한다. 기존 스테이지는 이 항목을 비워 두면 동작을 유지한다.

## 이벤트 ID

출격 칸의 ID가 해당 칸에 배치한 유닛의 전투 ID가 된다. 예를 들어 `출격1` 칸의 유닛은 대사 이후 이동·체력 변경 명령이나 생존 분기에서 `출격1`로 참조한다. 빈 칸은 전투 유닛을 만들지 않으므로 필수 이벤트가 참조할 출격 칸을 비우지 않도록 시나리오를 작성해야 한다.

출격 칸이 없는 기존 맵은 기존 방식으로 바로 시작한다. 스테이지 간 HP·EN·잔탄·경험치 이월 규칙은 이번에 변경하지 않았다.
