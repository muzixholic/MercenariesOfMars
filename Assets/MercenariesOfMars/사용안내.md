# MercenariesOfMars SRPG 기반 사용 안내

최신 진행·공방·상점·저장은 [인터미션 안내](인터미션안내.md), 출격·영입은 [아군 출격 배치 안내](아군출격배치안내.md)를 함께 참고하세요.

파일럿 성장과 적군 자동 레벨은 **화성의 용병단 → 설정** 메뉴에서 편집합니다. [성장 프리셋·적군 보정 설정 안내](파일럿성장프리셋안내.md)를 참고하세요.

첫 버전은 3D X/Z 평면의 사각 격자에서 아군 턴과 적군 턴이 번갈아 진행되는 전투 기반입니다. 씬, 프리팹, 기존 프로젝트 설정은 자동으로 수정하지 않습니다.

## 데이터 편집

Unity 상단의 `MercenariesOfMars > 기체 에디터`, `파일럿 에디터`에서 데이터를 각각 편집하고 `유닛 편성 에디터`에서 둘과 진영을 조합합니다. 기존 `캐릭터 능력치 에디터` 메뉴도 유닛 편성을 엽니다. [기체·파일럿 작성 순서와 현재 적용 범위](기체와파일럿안내.md)를 먼저 참고하세요. 같은 기체·파일럿 에셋을 여러 편성에서 공유할 수 있으며, 전투 시작 시 수치를 복사합니다. 유닛마다 고유 ID를 부여해야 합니다.

`MercenariesOfMars > 조립형 스크립트 에디터`에서 이벤트 에셋을 만들고 명령을 추가합니다. 명령 번호는 0부터 시작합니다. 대사, 대기, 체력 변경, 플래그 설정과 조건 분기, 체력 조건 분기, 이동, 공격, 턴 종료, 이벤트 종료를 지원합니다. 해당 명령에 필요한 항목만 표시됩니다. 에셋을 Inspector에서 선택해도 같은 편집기를 사용할 수 있습니다.

- 체력 변경: 양수는 회복, 음수는 피해입니다. 최대 체력으로 제한되며 전투 불능 유닛의 부활은 지원하지 않습니다.
- 플래그 조건 분기: 저장된 값이 지정한 값과 같으면 분기합니다. 아직 설정하지 않은 플래그는 거짓입니다.
- 체력 조건 분기: 대상의 현재 체력이 지정한 값 이하이면 분기합니다.
- 조건이 거짓이면 바로 다음 명령을 실행합니다. 무조건 분기는 항상 참인 플래그 조건으로 구성할 수 있습니다.
- 이동·공격은 현재 턴, 이동력, 점유 상태와 사거리 규칙을 적용합니다. 강제 이동 명령은 아닙니다.
- 잘못된 유닛 ID나 불가능한 행동은 이벤트를 중단하고 오류를 조작 패널에 표시합니다.
- 명령을 드래그해서 재정렬하면 분기 번호도 보정합니다. 분기 목적지를 삭제하면 오류를 표시하므로 새 목적지를 지정해야 합니다.
- 플래그는 캠페인 스테이지 사이에 이월하며 인터미션 저장·불러오기로 보존합니다. 단독 맵 테스트는 별도 진행 상태를 사용합니다.
- 무한 반복 방지를 위해 실행기별 최대 명령 수가 있습니다. 기본값은 1,000입니다.
- 대기 시간은 게임 시간 배율의 영향을 받지 않습니다. 대사는 사용자가 확인할 때까지 기다립니다.
- 데이터 저장 버튼으로 에셋을 저장할 수 있습니다. 일반 Unity Undo/Redo를 지원합니다.

예시: `플래그 설정(구출=true)` → `플래그 조건 분기(구출=true, 목적지=3)` → `체력 변경(아군1, -10)` → `대사(구출 성공)` 순서이면 체력 감소를 건너뜁니다.

## Inspector 연결 절차 — 사용자가 씬 변경을 승인한 뒤 적용

1. 빈 GameObject에 `GridBoard`를 추가합니다. 가로/세로 칸 수, 칸 크기, 격자 색, 진입 불가 칸을 지정합니다. 이 오브젝트의 로컬 X/Z 방향으로 보드가 확장됩니다. 좌표 `(0, 0)`은 첫 번째 칸입니다.
2. 다른 빈 GameObject에 `BattleController`를 추가하고 격자 보드와 전투 카메라를 지정합니다. 카메라는 보드 전체를 내려다보도록 배치합니다. 카메라를 생략하면 `MainCamera` 태그의 카메라를 사용합니다.
3. 초기 유닛 배치 목록에 고유한 ID, 캐릭터 에셋, 시작 칸을 입력합니다. 아군과 적군을 각각 한 명 이상 배치하고 장애물·다른 유닛과 겹치지 않게 합니다.
4. 시작 이벤트가 필요하면 `EventRunner`를 추가하고, 컨트롤러의 이벤트 실행기와 시작 이벤트에 연결합니다. 대사 확인을 위해 기본 조작 패널을 켜 두거나 별도 UI에서 `ContinueDialogue()`를 호출해야 합니다.
5. Play 모드에서 타이틀의 전투 시작을 누르고, 아군 캡슐을 클릭해 행동 메뉴를 엽니다. 이동을 선택한 뒤 색칠된 칸을 클릭하면 이동합니다. 공격 메뉴에서 스킬을 선택한 뒤 색칠된 공격 범위의 적을 클릭하면 공격합니다. 대기 버튼은 해당 유닛 행동을 끝내고, 턴 종료 버튼은 진영 전체의 턴을 끝냅니다. `G` 키 또는 격자 전환 버튼으로 격자 선을 숨기거나 표시합니다.

격자와 임시 유닛 모델은 실행 중 생성합니다. 맵 에셋이 연결되면 지형 표면·구조물도 맵 데이터로 표시합니다. 클릭 위치는 격자 평면과 광선의 교차점으로 계산하므로 바닥 Collider는 필요하지 않습니다. 자세한 작성 방법은 [맵 에디터 안내](맵에디터안내.md)를 참고하세요.

## 전투 규칙

- 유닛은 자기 진영 턴에 한 번 이동하고 한 번 공격하거나 대기합니다. 공격·대기는 행동을 끝냅니다. 이동을 생략하고 공격할 수 있습니다.
- 이동은 상하좌우이며 지형별 진입 비용을 합산합니다. 기본 비용은 1입니다. 아군을 포함한 생존 유닛의 칸을 통과할 수 없습니다.
- 무장 사거리는 맨해튼 거리의 최소~최대 구간입니다. 현재 피해는 `최대(1, 파일럿 공격력 + 개조 적용 무장 공격력 - 파일럿 방어력 - 대상 지형 방어 보정)`입니다. 반격·방어·회피와 전투 확인을 지원하며, 구조물의 사선 차단은 없습니다. 기체 장갑·조준·운동성을 반영하는 새 전투 공식은 미정입니다.
- 생존 유닛 전원이 행동을 마치면 다음 진영 턴으로 넘어갑니다. 적군 턴 다음 아군 턴에 라운드가 증가합니다.
- 맵에서 적 전멸 또는 아군 목표 칸 도달을 승리 조건으로 선택합니다. 아군 전멸은 패배입니다. 종료 후 전투 행동과 체력 변경은 거절합니다.
- 기본 적 AI는 사용 가능한 보유 스킬과 에너지를 기준으로 공격 가능한 칸을 찾고, 최소 사거리 안쪽이면 거리를 벌립니다. 공격할 수 있는 칸이 없으면 스킬 사거리까지의 차이가 작은 칸을 선택합니다. 장기 경로 계획과 전술 판단은 아직 없습니다.
- 시작 이벤트 실행 중에는 수동 조작과 자동 AI를 멈춥니다.

## 구현 파일

- `Runtime/CharacterDefinition.cs`: 캐릭터 데이터.
- `Runtime/BattleGrid.cs`: 격자, 도달 범위와 최단 경로 탐색.
- `Runtime/BattleSession.cs`: 전투 상태, 이동·공격·턴과 승패.
- `Runtime/GridBoard.cs`: 3D 좌표 변환, 격자 표시.
- `Runtime/BattleController.cs`: 씬 연결, 임시 모델, 마우스 조작, 기본 적 AI와 임시 조작 패널.
- `Runtime/EventSequence.cs`: 이벤트 명령 데이터와 유효성 검사.
- `Runtime/EventRunner.cs`: 이벤트 실행과 플래그.
- `Editor/CharacterEditorWindow.cs`: 캐릭터 능력치 창.
- `Editor/EventCommandDrawer.cs`: 명령별 입력 항목.
- `Editor/EventSequenceEditor.cs`: 이벤트 창, 순서 변경과 분기 보정.
- `Tests/Editor/BattleTests.cs`: 전투 규칙 검증.
- `Tests/Editor/EventEditorTests.cs`: 명령 재정렬·삭제·추가의 편집기 검증.
- `Tests/PlayMode/EventTests.cs`: 이벤트 실행과 AI·격자 통합 검증.
- 각 폴더의 `.asmdef`: 런타임, Editor와 테스트 어셈블리 분리.

## 현재 범위와 다음 확장

현재는 기능 검증용 엔진과 데이터 편집 도구입니다. 완성된 전투 씬이나 최종 게임 UI는 포함하지 않습니다. 고저차, 지형 비용, 이동 범위 하이라이트, 경로 애니메이션, 모델 교체 편집, 상태 이상, 성장·장비, 저장·불러오기, 이벤트 트리거 편집, 유닛 등장 명령은 후속 확장 대상입니다. 이번 단계에서는 시작 이벤트 연결과 코드에서의 `EventRunner.Play()` 호출을 지원합니다.

## 연결된 예시 씬

사용자 승인에 따라 `Assets/Scenes/SampleScene.unity`에 전투 구성을 연결했습니다. 이 씬을 열고 Play를 누르면 시작 안내 대사 두 개가 나옵니다. 조작 패널의 `대사 계속`을 두 번 누르면 아군을 조작할 수 있습니다.

- `SRPG 전투/격자 보드`: 10×8, 칸 크기 1, 격자 표시 켜짐. 중앙 `(4,3)`, `(4,4)`, `(5,3)`, `(5,4)`는 진입 불가입니다.
- `SRPG 전투/전투 진행`: 보드, 메인 카메라, 이벤트 실행기, 시작 이벤트와 유닛 네 명의 참조가 연결되어 있습니다. 자동 적군 행동이 켜져 있습니다.
- `Main Camera`: 직교 카메라, 크기 5.8. 왼쪽 조작 패널을 피해 전장이 오른쪽에 보이도록 배치했습니다.
- `Assets/MercenariesOfMars/Data`: 아군 기사·궁수, 적군 경비병·척후병 능력치 에셋과 `전투_시작안내.asset`, 바닥·장애물 재질이 있습니다.
- 유닛 ID는 `아군_기사`, `아군_궁수`, `적군_경비병`, `적군_척후병`입니다. 시작 칸은 각각 `(1,2)`, `(1,5)`, `(8,2)`, `(8,5)`입니다.

추가 Inspector 연결 없이 실행할 수 있습니다. 이후 능력치를 바꾸려면 해당 캐릭터 에셋을 편집하고, 배치를 바꾸려면 `전투 진행`의 초기 유닛 배치 목록을 수정하세요. 장애물을 바꿀 때는 보드의 진입 불가 칸과 시각 장애물 오브젝트를 함께 맞추세요. 이 예시 씬에서 사용하는 캡슐은 실행 중에만 생성되므로 편집 모드에서는 보이지 않습니다.


## 캐릭터별 스킬과 에너지

`MercenariesOfMars > 스킬 에디터`에서 스킬을 만들고 이름, 공격력, 명중 보정, 최소 사거리, 최대 사거리, 소비 에너지, 설명을 편집합니다. 사거리는 `1~1`, `1~3`, `2~3`처럼 양 끝을 포함합니다. `2~3`은 바로 옆의 적을 공격할 수 없습니다. 최소 사거리는 1 이상이며 최대 사거리를 최소보다 작게 입력하면 최소값까지 보정합니다. 소비 에너지는 0부터 설정할 수 있습니다.

`MercenariesOfMars > 캐릭터 능력치 에디터`의 보유 스킬 목록에서 `+`로 항목을 추가하고 스킬 에셋을 지정하세요. 항목 선택 후 `−`로 삭제할 수 있으며, 삭제해도 스킬 에셋 자체는 지워지지 않습니다. 드래그로 순서를 변경하고 각 항목의 `편집` 버튼으로 스킬 에디터를 열 수 있습니다. 같은 스킬을 여러 캐릭터가 공유해도 됩니다. 빈 항목과 중복 항목, 최대 에너지보다 비싼 스킬에는 안내를 표시합니다. 중복·빈 항목은 전투 시작 시 제외합니다.

전투에서는 유닛을 선택하면 보유 스킬 목록과 현재/최대 에너지가 표시됩니다. 처음에는 사용 가능한 첫 스킬이 선택되며 원하는 스킬 버튼을 누른 뒤 적을 클릭하세요. 소비량보다 에너지가 적은 스킬 버튼은 비활성화됩니다. 공격이 성공하면 에너지가 차감되고 유닛의 행동이 끝납니다. 사거리 밖, 미보유 스킬, 에너지 부족 등으로 실패하면 에너지와 행동을 소모하지 않습니다. 스킬이 없는 캐릭터는 이동·대기만 할 수 있습니다.

에너지는 전투 시작 시 최대치로 채웁니다. 이번 버전에서는 턴별 자동 회복이나 별도의 에너지 회복 명령을 제공하지 않습니다. 장기 전투용으로 소비량 0의 스킬을 하나 넣을 수 있습니다. 캐릭터 공격력은 스킬 공격력에 더해 피해에 반영합니다. 기존 캐릭터 공격력 값을 그대로 사용하고 다시 편집할 수 있습니다. 사거리는 스킬에서 설정하며 기존 캐릭터 사거리 필드는 이전 데이터 호환을 위해 숨겨 보존합니다. 캐릭터와 스킬 수치는 전투 시작 시 복사하므로 진행 중 원본 에셋 수정은 다음 전투부터 반영됩니다.

조립형 이벤트의 `공격` 명령에도 사용할 스킬을 지정할 수 있습니다. 지정한 스킬을 공격자가 보유하지 않았거나 사용할 수 없으면 이벤트가 중단됩니다. 기존 이벤트와의 호환을 위해 미지정 시 공격자가 사용할 수 있는 첫 보유 스킬을 선택합니다.

예시 캐릭터 네 명에는 각각 소비량 0의 스킬과 에너지를 쓰는 강한 스킬을 연결했습니다. `Assets/MercenariesOfMars/Data/Skills`에서 수정할 수 있습니다. 씬의 추가 연결 설정은 필요하지 않습니다.

## 공격·명중·회피와 스킬 명중 보정

캐릭터 에디터와 캐릭터 에셋 Inspector에서 공격력(0 이상), 명중(0~100%), 회피(0~100%)를 설정합니다. 스킬 에디터와 스킬 에셋 Inspector에서는 명중 보정(-100~+100%p)을 설정합니다. 기본값은 명중 100%, 회피 0%, 스킬 명중 보정 0%p입니다. 기존 캐릭터의 공격력 값은 유지됩니다.

- 명중률 = `명중 + 스킬 명중 보정 - 대상 회피`, 최종값은 0~100%로 제한합니다.
- 명중 80%, 스킬 보정 +10%p, 대상 회피 20%이면 실제 명중률은 70%입니다.
- 명중 시 피해 = `최대(1, 캐릭터 공격력 + 스킬 공격력 - 대상 방어력)`입니다.
- 공격력 10, 스킬 공격력 15, 방어력 3이면 예상 피해는 22입니다. 결과에 표시하는 실제 피해는 대상의 남은 체력을 넘지 않습니다.
- 명중률 0%는 항상 빗나가고 100%는 항상 명중합니다. 그 사이는 매 공격마다 확률 판정합니다.
- 빗나감도 실행된 공격이므로 에너지를 소모하고 해당 유닛의 행동을 끝냅니다. 사거리·에너지 부족 등으로 실행이 거절된 공격은 계속 소모하지 않습니다.
- 조립형 이벤트에서도 빗나감은 명령 실행 성공으로 처리하며 다음 명령을 진행합니다.
- 전투 패널에는 선택 유닛의 능력치, 각 스킬의 명중 보정, 현재 공격할 수 있는 대상별 예상 명중률·피해와 최근 공격의 명중/빗나감 결과가 표시됩니다.
- 기본 적 AI도 스킬별 명중률을 반영한 기대 피해를 고려합니다.

능력치와 보정은 전투 시작 시 복사됩니다. 에셋을 편집하면 다음 전투부터 반영되며 씬의 추가 연결은 필요하지 않습니다. 확률 테스트는 난수를 주입해 판정 경계를 검증하므로 실행할 때마다 결과가 바뀌지 않습니다.


## 스킬별 이동 후 사용 제한

스킬 에디터 또는 스킬 에셋 Inspector의 `이동 후 사용 가능`을 켜거나 끌 수 있습니다. 기본값은 켜짐이며 기존 스킬도 이동 후 사용할 수 있습니다.

- 켜짐: 해당 턴에 이동한 뒤 사용할 수 있습니다.
- 꺼짐: 해당 턴에 한 번이라도 실제 이동했다면 사용할 수 없습니다. 이동하지 않고 공격하는 것은 가능합니다.
- 같은 칸 클릭, 점유 칸이나 격자 밖으로의 실패한 이동은 이동으로 취급하지 않습니다.
- 다음 자기 진영 턴이 시작되면 이동 기록이 초기화되어 정지 전용 스킬을 다시 쓸 수 있습니다.
- 이동 후 불가 스킬을 선택한 상태에서 이동하면 선택이 해제됩니다. 다른 사용 가능한 스킬을 선택하세요. 비활성화된 버튼에는 이동 후 불가 여부가 표시됩니다.
- 사용이 거절되면 체력·에너지·행동을 소모하지 않고 명중 판정도 하지 않습니다.
- 캐릭터 에디터의 보유 스킬 목록에도 이동 후 가능/불가가 표시됩니다.
- 적 AI와 조립형 이벤트에도 같은 규칙을 적용합니다. 정지 전용 스킬만 가진 AI는 사거리로 접근 후 대기하고 다음 턴에 공격할 수 있습니다.

이 설정 역시 전투 시작 시 복사됩니다. 수정한 값은 다음 전투부터 적용됩니다. 씬이나 프리팹의 추가 연결은 필요하지 않습니다.

## 적 공격에 대한 반격·방어·회피

적군이 아군을 공격하면 피해를 바로 적용하지 않고 전투 패널에 대응 선택을 표시합니다. 적의 이름과 사용 스킬, 공격받는 아군의 체력·에너지, 기본 피격률·예상 피해를 확인할 수 있습니다. 선택하는 동안 적 AI, 다른 전투 행동, 턴 종료와 체력 변경은 중단됩니다. 적의 공격 에너지도 선택이 끝나고 공격을 실제 적용할 때 차감합니다.

- **반격**: `반격 · 스킬 선택`을 누르고 보유 스킬 중 하나를 선택합니다. 사거리(최소·최대 모두 적용), 에너지, 스킬 보유 여부를 검사합니다. 유효한 스킬이 없으면 반격 버튼이 비활성화되며 방어·회피는 계속 선택할 수 있습니다.
- 반격을 선택하면 적 공격을 원래 피해·명중률로 먼저 받습니다. 살아 있으면 선택한 스킬로 한 번 반격합니다. 반격으로 다시 반격이 발생하지 않습니다.
- 피격으로 전투 불능이 되면 반격하지 않으며 반격용 에너지도 소모하지 않습니다. 반격이 빗나가면 스킬 에너지는 소모합니다. 적 공격이 빗나가도 반격할 수 있습니다.
- 반격은 자기 턴의 공격 행동과 별개입니다. 이전 자기 턴에 행동을 마쳤거나 이동했어도 반격할 수 있습니다. `이동 후 사용 불가`는 이전 아군 턴의 이동 이력으로 반격을 막지 않습니다. 새로 공격받을 때마다 다시 선택하며 에너지는 누적 소모됩니다.
- **방어**: 방어력 등을 계산한 원래 피해를 절반으로 줄이고 올림합니다. 피해 7→4, 8→4, 1→1입니다. 남은 체력으로 자르기 전에 절반으로 계산하므로 치명적인 공격을 반드시 생존하는 것은 아닙니다. 반격하지 않으며 방어 자체는 에너지를 소모하지 않습니다.
- **회피**: 명중·스킬 보정·회피 능력치를 계산한 최종 피격률을 절반으로 줄입니다. 100%→50%, 65%→32.5%입니다. 명중 판정은 0.01% 단위 난수를 사용하며, 명중하면 원래 피해를 받습니다. 반격하지 않으며 회피 자체는 에너지를 소모하지 않습니다.

피격과 반격을 모두 처리한 뒤 승패와 턴 전환을 판정합니다. 결과 패널에는 선택한 대응과 피격·반격 결과가 표시됩니다. 적→아군 공격의 대응은 플레이어가 고르고 아군→적 공격의 대응은 적 AI가 고릅니다. 실제 전투는 아래의 전투 확인 단계 이후에 판정합니다.

조립형 이벤트의 공격도 대응과 최종 전투 확인을 기다리고, 전투 판정이 끝나야 다음 명령으로 진행합니다. 별도 UI를 만들려면 `BattleController.ChooseReaction(ReactionChoice, 스킬 인덱스)`를 호출하세요. 모델에서 직접 처리할 때는 `BattleSession.PendingAttack`, `CanCounterattack()`, `ResolveReaction()`을 사용할 수 있습니다. `TryAttack()`의 참은 공격 요청 접수 성공을 뜻하며 적→아군이면 아직 대응 대기 상태일 수 있습니다. 기본 조작 패널을 끈 경우 대응 선택 UI를 별도로 연결해야 합니다.

## 적의 자동 대응과 최종 전투 확인

기본 전투 컨트롤러에서는 아군이 공격해도 즉시 피해를 적용하지 않습니다. 적의 대응을 먼저 결정하고 양측의 선택을 전투 확인 창에 표시합니다. 적군이 공격하면 내 반격·방어·회피 선택 후 같은 확인 창이 열립니다.

확인 창에서 공격자와 방어자, 공격·반격 스킬, 최종 명중률, 명중 시 예상 피해, 소모 에너지와 현재 체력을 확인할 수 있습니다. 긴 내용은 창 안에서 스크롤하며 진행·취소 버튼은 창 하단에 고정됩니다. 적이 대응하는 경우 판단 이유도 표시합니다. 예측값이며 실제 명중 판정은 `전투 진행`을 누를 때 실행합니다. 생존하지 못하면 반격이 취소되는 규칙은 그대로입니다.

적 AI는 사용할 수 있는 반격 스킬만 후보로 삼고 방어·회피와 비교합니다. 전투 불능 확률이 낮은 선택을 먼저 고르고, 같으면 공격자를 쓰러뜨릴 가능성, 예상 반격 피해에서 예상 피격 피해와 에너지 비용을 뺀 값을 비교합니다. 방어로 생존할 수 있으면 방어하고, 방어로도 치명적이면 회피로 위험을 줄일 수 있습니다. 안전하게 효과적인 반격이 가능하면 해당 스킬을 고릅니다. 판단에 난수를 사용하지 않으므로 같은 상태에서 취소·재시도하면 같은 대응이 나옵니다.

- `전투 진행`: 양측의 공격·반격을 판정하고 체력·에너지·행동을 소모한 뒤 승패와 턴을 처리합니다.
- 아군이 공격할 때 `공격 취소`: 공격 전 선택으로 돌아갑니다. 체력·에너지·공격 행동은 소모하지 않습니다. 공격 전에 이미 한 이동은 되돌리지 않습니다.
- 적군이 공격할 때 `취소 · 대응 다시 선택`: 적의 공격은 유지하고 내 대응 선택으로 돌아갑니다. 아직 체력·에너지·행동을 소모하지 않으며, 적 AI가 다음 행동으로 넘어가지 않습니다.
- 확인 대기 중 다른 유닛 조작·공격·턴 종료와 이벤트 후속 명령은 정지합니다. 확인이나 취소를 두 번 호출해도 전투가 중복 적용되지 않습니다.
- 이벤트의 아군 공격을 취소하면 해당 이벤트를 명시적인 취소 안내와 함께 중단합니다. 적 공격에서 대응을 바꾸는 경우에는 계속 확인을 기다립니다.

기본 씬에서는 추가 Inspector 설정 없이 동작합니다. 커스텀 UI에서는 `ChooseReaction()` 후 `ConfirmCombat()` 또는 `CancelCombat()`을 호출하세요. 모델을 직접 생성하는 도구는 `new BattleSession(..., requireConfirmation: true)`로 같은 확인 단계를 사용할 수 있습니다. `BattleController.RequireConfirmation`은 기본 참이며 씬 설정을 추가하지 않습니다. 기존 모델의 즉시 판정 API와 규칙 검증 도구를 위한 호환 모드는 유지합니다.

## 전투 연출 화면

전투 확인 창에서 **전투 진행**을 누르면 임시 전투 무대와 전용 카메라로 전환합니다. **공격 효과 → 공격 피해 숫자와 체력 감소 → 반격 효과 → 반격 피해 숫자와 체력 감소**를 순서대로 재생한 뒤 격자 화면으로 돌아옵니다. 방어·회피를 선택했거나 피격으로 전투 불능이 되면 반격 과정은 생략합니다. 빗나간 공격에는 ‘빗나감’을 표시합니다.

연출 중에는 유닛 조작, 적 AI, 턴 전환 및 공격 이벤트의 다음 명령을 대기시킵니다. 결과 판정과 에너지 소모는 확정 시 한 번만 적용하며 화면의 체력은 순서대로 감소합니다. **연출 건너뛰기**는 확정된 결과를 유지하고 즉시 복귀합니다. 현재 캐릭터 모델은 임시 캡슐이고 공격 효과는 이동하는 빛 구체입니다.

### Inspector 설정

## 유닛 행동 메뉴와 이동 범위

아군 턴에 아직 행동하지 않은 아군을 클릭하면 유닛 오른쪽에 **이동 / 공격 / 대기** 메뉴가 표시됩니다. 화면 가장자리에서는 메뉴가 화면 안으로 들어오도록 위치를 보정합니다. 기존의 빈 칸 클릭 이동은 이동 모드를 먼저 선택하는 방식으로 변경했습니다.

- **이동**: 갈 수 있는 칸을 파란색으로 채웁니다. 이동력, 장애물, 다른 유닛의 점유 상태를 반영합니다. 색칠된 칸을 클릭하면 이동하고 메뉴에서 다음 행동을 선택할 수 있습니다. 이동을 마친 유닛은 이동 버튼이 비활성화됩니다.
- **공격**: 행동 메뉴를 덮는 스킬 선택 창에서 스킬을 고른 뒤 공격 범위 안의 적을 클릭합니다. 기존 전투 확인과 반격 선택 흐름을 그대로 사용합니다.
- **대기**: 선택 유닛의 행동을 끝내고 메뉴와 이동 표시를 닫습니다.
- 이동 모드에서 공격으로 전환하거나 아군을 바꾸면 이동 표시를 지웁니다. Esc 또는 마우스 오른쪽 버튼으로 현재 모드를 취소할 수 있습니다.
- 타이틀, 이벤트, 적군 턴, 전투 확인, 연출 중에는 메뉴를 숨기고 이동 표시를 제거합니다. 격자 선을 G로 꺼도 이동 모드의 색칠은 유지됩니다.

## 스킬 선택 창·공격 범위·자원 막대

오른쪽 행동 메뉴의 **공격**을 누르면 같은 위치에 **스킬 선택 창**이 열려 행동 메뉴를 덮습니다. 스킬 목록은 이 창에서 선택하며, 왼쪽 패널에는 선택 스킬 요약을 표시합니다. 목록이 길면 스크롤할 수 있고, **돌아가기** 또는 Esc/오른쪽 클릭으로 행동 메뉴에 돌아갑니다. 에너지 부족이나 이동 후 사용 불가인 스킬은 선택할 수 없으며 이유를 표시합니다.

스킬을 선택하면 선택 창과 행동 메뉴가 모두 닫히고 **공격 범위가 주황색**으로 표시됩니다. 최소·최대 사거리를 적용하므로 거리 2~3 스킬은 인접 칸을 칠하지 않습니다. 보드 밖의 칸은 제외합니다. 기존 전투 규칙과 동일하게 맨해튼 거리로 계산하며, 장애물이나 유닛의 점유 여부로 공격 사거리를 차단하지 않습니다. 범위 안의 적을 클릭하면 전투 확인으로 넘어갑니다. 취소·선택 변경·대기·턴 전환·이벤트·전투 확인 시 범위 표시를 제거합니다. G로 격자 선을 꺼도 범위 색칠은 유지됩니다.

선택한 아군 머리 위에 가로 막대 두 개를 표시합니다. **HP는 빨간색, 에너지는 파란색**이며, 막대 안에 **현재량/최대량**을 표시합니다. 체력 변경과 에너지 소모를 반영하며, 최대 에너지가 0이면 0/0의 빈 막대를 표시합니다. 막대는 유닛 위치를 따라가고, 선택 해제·행동 종료·전투 연출 중에는 숨깁니다.

## 상세 능력·빈 칸 우클릭 메뉴

## 적 공격 범위와 턴 전환 안내

적군이 아군을 공격해 대응 선택을 기다리는 동안, 공격해 오는 **해당 스킬의 최소·최대 사거리**를 빨간색으로 칠합니다. **공격자 칸은 노란 테두리**, **피격 아군 칸은 청록 테두리**로 표시하고, 유닛 위에도 역할·이름을 표시합니다. 대응 선택 후 전투 확인 중에도 유지하며, 대응을 다시 선택해도 유지합니다. 전투 확정 후 연출로 넘어갈 때 표시를 정리합니다. 격자 선 표시를 꺼도 범위·대상 표시는 유지됩니다.

아군 턴·적군 턴으로 바뀌면 화면 중앙에 **아군 턴 / 적군 턴**과 현재 라운드를 잠시 표시합니다. 최초 전투 시작에도 아군 턴을 안내합니다. 일반 체력 변경이나 선택 변경으로는 전환 안내를 다시 띄우지 않습니다. 적 AI는 안내가 끝난 뒤 행동하며, 전투 연출·대응 선택·승패 화면에서는 전환 안내를 겹쳐 표시하지 않습니다.

## 맵 중앙 정렬과 카메라 조작

대응 선택·반격 스킬 선택·적 공격의 전투 확인 창은 다른 선택 창과 동일하게 **화면 가운데** 정렬합니다.

전투를 시작하거나 다시 시작하면 카메라가 보드 중심을 화면 중앙에 맞춥니다. 기존 시점 각도는 유지하고, 직교 카메라는 맵 크기와 화면 비율에 맞춰 초기 확대 크기를 계산합니다. 카메라 위치는 실행 중에만 조정하며 저장된 씬은 바꾸지 않습니다.

- **마우스 휠 위/아래**: 확대/축소합니다.
- **마우스 왼쪽 버튼을 누르고 드래그**: 지도를 잡아 끌듯 보드 평면을 따라 시점을 이동합니다.
- 8픽셀 이상 움직이면 드래그로 판정합니다. 짧은 클릭은 버튼을 뗄 때 선택·이동·공격으로 처리하고, 드래그가 끝날 때는 전투 행동을 실행하지 않습니다.
- 상세 능력·설정·스킬 목록·우클릭 메뉴 위의 입력은 해당 UI가 처리합니다. 대응·전투 확인·연출·이벤트·적 자동 행동 중에는 맵 조작을 잠급니다.
- 과도한 확대/축소와 보드에서 지나치게 멀어지는 이동을 제한합니다. 재시작하면 초기 중앙 시점으로 돌아옵니다.

추가 Inspector 설정은 필요 없습니다. `BattleMapCamera`는 전투 시작 시 자동으로 생성합니다. 실행 중 해당 컴포넌트의 최소/최대 직교 크기, 휠 감도, 드래그 판정 거리를 조절할 수 있습니다. 원근 카메라는 휠로 시야각 20~75도 안에서 조절합니다.

변경 파일: `Runtime/BattleController.cs`, `Runtime/BattleMapCamera.cs`, `Tests/PlayMode/MapCameraTests.cs`와 새 스크립트 메타 파일, 이 안내 문서. 씬·프리팹은 수정하지 않았습니다.

## 행동 완료 색상과 대사 진행 입력

아군·적군 모두 **공격 또는 대기로 행동을 마치면 맵 위 모델을 회색**으로 표시합니다. 턴 종료로 행동이 마감된 유닛도 회색으로 바뀌고, 다음 자기 진영 턴에 행동이 초기화되면 기존 파란색/빨간색으로 돌아옵니다. 이동만 한 유닛은 행동할 수 있으므로 진영 색을 유지합니다. 공격이 빗나가도 행동을 소모했으면 회색입니다. 원본 캐릭터 에셋과 재질 에셋은 수정하지 않습니다.

대사창의 **대사 계속 버튼을 제거**했습니다. **대사창 안을 마우스 왼쪽 버튼으로 클릭**, **스페이스바**, **엔터**, **숫자패드 엔터** 중 하나로 다음 대사 페이지를 표시합니다. 키를 계속 누르고 있는 것만으로는 다음 페이지를 반복해서 넘기지 않습니다. 대사창 밖 클릭은 대사를 넘기거나 전투 행동을 실행하지 않습니다. 대사 중에는 맵 드래그·확대도 잠급니다.

추가 Inspector 설정은 필요 없습니다. 씬·프리팹은 수정하지 않았습니다. 변경 파일: `Runtime/BattleController.cs`, `Tests/PlayMode/UnitCommandTests.cs`, 이 안내 문서.
